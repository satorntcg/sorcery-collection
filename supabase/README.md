# Supabase Project Files

Keep database schema, views, policies, functions, and seed data here so frontend changes can be reviewed alongside database changes.

Recommended layout:

- `migrations/` - ordered SQL migration files, ideally generated by the Supabase CLI.
- `schema.sql` - optional full schema snapshot for Codex/review context.
- `views.sql` - optional current definitions for app-facing views.
- `policies.sql` - optional row-level security policies.
- `functions/` - Supabase Edge Function source if you want it versioned here.

The frontend currently reads these app-facing views:

- `v_inventory_dashboard`
- `v_latest_prices`
- `v_active_alerts`
- `v_ebay_active`
- `v_ebay_sold`
- `v_global_pnl`
- `v_tcgplayer_active`
- `v_tcgplayer_sold`
- `v_tcgplayer_pnl`
- `v_box_pnl`
- `v_youtube_opening_summary`

For now, you can paste/export SQL definitions into `schema.sql`, `views.sql`, and `policies.sql`. Longer term, use the Supabase CLI so changes land as timestamped files in `migrations/`.
